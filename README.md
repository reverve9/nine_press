# nine_press

판면 규칙 기반 문서 조판. **content(JSON) + rules(CSS) → HTML → PDF.**

키노트를 쓰지 않는다. 산출물은 PDF 이고, 그 앞의 모든 단계가 파일이다.

---

## 왜 이 구조인가

문안의 **원본이 하나**여야 한다. 종전에는 빌드 스크립트·생성된 HTML·브라우저 localStorage·「편집본 저장」 파일 넷이 각각 문안을 들고 있었고 서로를 몰랐다. 빌드를 한 번 돌리면 뒤 셋이 조용히 죽었다.

```
content/   유일 원본. 사람이 고치는 곳은 여기뿐이다
rules/     판면·격자·활자·색·블록 규격. 규칙이 곧 CSS 다
out/       파생물. 버려도 된다 (.gitignore)
```

**좌표와 높이를 데이터에 적지 않는다.** 규칙이 계산한다. 사람이 넣는 것은 유형·폭·글자뿐이다.

## 쓰는 법

```bash
bash scripts/fonts.sh                      # 최초 1회. Paperlogy · Pretendard
node scripts/build.js content/sokcho/실행계획서.json
open out/html/실행계획서.html

npm i -D playwright && npx playwright install chromium   # 최초 1회
node scripts/pdf.js out/html/실행계획서.html               # 벡터 PDF
```

확인용 출력은 브라우저에서 **⌘P → PDF로 저장**으로도 된다. `print-color-adjust:exact` 가 들어 있어 배경 그래픽 체크 없이 색이 나온다.

### 산출 HTML 은 자기완결이다

| 명령 | 나오는 것 | 쓸 때 |
|---|---|---|
| `build.js <json>` | **CSS 내장 · 폰트 상대경로** · 30KB | 평소 |
| `build.js <json> --embed` | **CSS·폰트 전부 내장** · 6.8MB | 남에게 보낼 때 · 다른 머신 |
| `build.js <json> --link` | `<link>` 로 CSS 연결 | 규칙을 고치며 새로고침할 때 |

> **CSS 를 `<link>` 로 걸지 않는 이유.** 파일을 다른 폴더로 옮기거나 메일로 보내는 순간
> 판면이 통째로 날아가고, 받은 사람은 그게 경로 문제인지 알 수 없다. 실제로 한 번 물렸다.
> `--embed` 는 규칙에서 실제로 쓰는 굵기(400 · 700 · 800)만 넣는다. 14종을 다 넣으면 19MB 가 된다.

## 도구 (껍데기)

```bash
npm install
npm run dev            # http://localhost:4400
```

```
┌──────────────┬─────────────────────────┐
│ 사이드패널     │  판본                    │
│  260px       │  2340×1654 를 창에 맞춤   │
│  문서 ▾       │                         │
│  면 목록       │   [iframe]              │
│  블록 목록     │                         │
│  빌드 · PDF   │                         │
└──────────────┴─────────────────────────┘
```

- **패널은 한 칸이고 안에서 파고든다** — 면 목록 → 블록 목록 → (다음 단계) 블록 폼.
  셋으로 벌리면 판본이 좁아진다. 2340폭을 세로와 함께 보려면 오른쪽을 넓게 둬야 한다
- **판본은 iframe** 이고 `/api/preview` 가 **산출과 같은 `render()`** 를 부른다.
  미리보기와 결과물이 다를 수 없다
- 폰트는 `/api/font/*` 로 나간다. `public/` 에 복사본을 두지 않는다 — 복사본이 생기면 어느 쪽이 진짜인지 흐려진다
- **`next build` 를 돌리지 않는다.** dev 전용이라 `.next` 가 깨질 경로가 없다.
  그래서 `npm run build` 를 일부러 만들지 않았다 (문서 빌드는 `npm run build:doc`)

**블록 폼은 아직 없다.** 문안 수정은 `content/**.json` 을 직접 고치고 다시 빌드한다.

## 데이터 모양

면은 **행**으로 쌓고, 행 안에 **열**을, 열 안에 **블록**을 넣는다. 열에 폭만 준다.

```
면 ─ 행 ─ 열(폭) ─ 블록 ─ 내용[]
```

```json
{
  "번호": "04",
  "제목": "사전분석과 기초 현황 조사",
  "메타": "선정 · 협약 직후 1주 · **10개소 전수**",
  "우측": { "수치": "15", "단위": "조사 항목" },
  "행": [{ "열": [
      { "폭": 1, "블록": [ { "라벨": "…", "내용": [ … ] } ] }
  ]}],
  "실무확인": ["…"]
}
```

### 규칙

| | |
|---|---|
| **폭** | **1 / 2 / 3 정수만.** 소수 비율을 쓰지 않는다 |
| **한 행** | 폭 합이 3 을 넘으면 다음 줄로 내려간다 |
| **채움** | 열의 **마지막 블록**이 남는 높이를 채운다. `"채움": false` 로 해제 |
| **행 채움** | 면의 **마지막 행**이 남는 높이를 채운다 |
| **여백** | 남으면 그대로 둔다. 늘려 채우지 않는다 |
| **밀도** | 한 면에 블록 6 개를 넘지 않는다. 넘치면 **활자를 키우지 말고 내용을 덜어낸다** |

### 블록

```json
{ "이름": "수행 방식",
  "배경": "or",            // 생략(흰) | fill 연회색 | or 주황 | nv 남색 | gr 연녹
  "라벨": "수행 방식",      // .bl  회색 소형
  "제목": "채점 방식",      // .bt  남색 굵은 제목. 라벨과 택일
  "내용": [ … ] }
```

### 내용 — 네 가지

```json
{ "목록":   ["…", "…"] }
{ "번호목록": ["…"] }
{ "문단":   "…" }
{ "표":     { … } }
```

전부 `"위여백": 10` 을 붙일 수 있다(`calc(10*var(--u))`).

### 표

```json
{ "표": {
    "밀도": "cp",                       // 생략(기본) | cp 촘촘 | xs 조밀
    "열":  [ {"폭":"34%"}, {"폭":"22%","정렬":"c","강조":"n"}, {"정렬":"c"} ],
    "머리": ["항목", "배점", "문항"],
    "행":  [ ["품질","20","4"],
             {"강조":"sum", "칸":["**합계**","100","**20**"]} ],
    "묶음": [ {"이름":"운영", "항목":["…","…"]} ],   // 행과 택일. rowspan
    "합계": ["**합계**","100","**20**"]              // 맨 끝 남색 강조행
} }
```

`정렬` `c`/`r` · `강조` `n`(Paperlogy 남색 숫자)은 **열 단위**로 준다. 칸마다 적지 않는다.

### 인라인 표기

| 쓰는 것 | 나오는 것 |
|---|---|
| `**굵게**` | `<b>` |
| `{TBD}` | 회색 점선 배지 — **수행사가 채운다** |
| `{TBD협의}` | 주황 점선 배지 — **주관기관 확인 후 확정** |
| `{→05}` | 면 연결 표기 `→ 05` |

문자열은 이스케이프하지 않는다. `&nbsp;` 같은 것을 그대로 써도 된다.

## 구조

```
rules/page.css     판면 규칙. 2340×1654 · 여백 100 · 3열 균등 694 · 간격 29
rules/fonts.css    @font-face. 폰트가 파일에 박혀 환경을 안 탄다
render/index.js    render(doc) → HTML 문자열. 프레임워크를 모른다
render/inline.js   인라인 표기
content/<사업>/     사업별 네임스페이스. 도구는 범용, 콘텐츠는 사업별
scripts/build.js   content → out/html
scripts/pdf.js     out/html → out/pdf (playwright · 벡터)
scripts/shot.py    면 단위 PNG. 재현 대조용
_legacy/           기존 완성본. 재현 대상이지 수정 대상이 아니다
app/               (나중) Next 화면 — 면 목록 · 블록 폼 · 미리보기 · 내보내기
```

**렌더러는 순수 함수다.** Next 라우트도, CLI 도, 검증 스크립트도 같은 함수를 부른다. 껍데기를 갈아치워도 렌더러는 그대로다.

## 검증 기록

`content/sokcho/실행계획서.json` 의 04·05면을 렌더해 확정본(`_v2_08171540`)과 픽셀 대조.

```
04면  0px / 3,870,360   완전 일치
05면  0px / 3,870,360   완전 일치
```

렌더 조건 — 2340×1654 · `device_scale_factor=1` · `transform:none` · 폰트 주입 후 `document.fonts.ready`.

> 여러 면을 한 문서에 담아 면 단위로 캡처하면 문서상 y 위치 차이 때문에
> 안티에일리어싱이 ±1 채널 흔들린다(17px 수준). 대조할 때는 **한 면씩 단독으로** 뽑는다.

## 안 만드는 것

드래그·자유 배치 / 폰트·크기·색 고르는 UI / 되돌리기 스택 / 이미지 편집 / 애니메이션 / 동시 편집 / 로그인 / 클라우드 동기화 / **템플릿을 화면에서 디자인하는 기능**

마지막 항목이 중요하다. **템플릿은 화면에서 만들지 않는다.** 새 구성이 필요하면 코드에 추가한다. 이 선을 열면 결국 편집기가 되고, 편집기가 되는 순간 규칙이 무너진다.

DB 도 지금은 두지 않는다. JSON 이 **git diff 로 보이고 · 손으로 고칠 수 있고 · 백업이 자명하다.**
버전 이력과 문서 간 검색이 필요해지는 시점에 넣는다. 그때 옮겨도 데이터 모양이 같아 비용이 없다.
