# P2.5-a 구현 프롬프트 — 세로 12칸 (동작)

작성 2026-08-19 · 대상 `/Volumes/BridgeNine/NINE_DEV/PROJECT/NINE_press`
선행 **P2-g**(하한 3칸). **P2-g 를 아직 안 돌렸으면 그것부터 돌린다.**

---

## §0 역할

**행 높이를 세로 12칸 눈금으로 고정할 수 있게 한다.**

가로가 열의 폭을 정했듯 세로는 행의 높이를 정한다. **다만 선택적이다** — 칸 수를 안 주면 지금대로 콘텐츠가 정한다.

**이번에 `render/index.js` 를 연다.** P0~P2 에서 안 건드린 파일이다. 순수 함수인 성격은 그대로 둔다.

**이 턴은 동작만 만든다.** 칩 · 끌기 · 격자 세로 띠는 P2.5-b 다.

---

## §1 규칙 — 먼저 읽는다

| | |
|---|---|
| ① | **세로 칸은 행에만 준다.** 열 안 블록 다수는 지금대로 마지막이 남는 높이를 채운다 |
| ② | **안 주면 자동.** 지금 동작이 기본이다 |
| ③ | **세로 합은 강제하지 않는다.** 가로와 다르다 — 고정 행들의 합이 12를 넘으면 넘침으로 잡힌다 |
| ④ | **세로 하한 2칸.** 1칸(83px)은 라벨만 들어간다 |
| ⑤ | **실무확인 띠도 선택적으로 칸 수를 갖는다.** 안 주면 지금대로 내용 높이(230px) |
| ⑥ | **백분율로 계산한다.** 판면 변종마다 `.bd` 높이가 달라 절대값을 박으면 어긋난다 |

**값**

```
높이(n) = calc((100% - 319px) / 12 * n + (n - 1) * 29px)      319 = 11 × 29
```

| 칸 | 실행계획서 `.bd` 1316 | 시뮬레이션 `.sim` 1358 |
|---|---|---|
| 2 | 195.2 | 202.2 |
| 3 | 307.2 | 317.7 |
| 4 | 419.3 | 433.3 |
| 5 | 531.4 | 548.9 |
| 12 | 1316 | 1358 |

## §2 작업 범위

### 2-1. `rules/page.css` **맨 끝**에 덧붙임

```css
/* ────────────────────────────────────────────────────────────
   ㉘ 세로 12칸  (2026-08-19)

   행에 --h 가 있으면 그 칸 수의 높이로 고정한다. 없으면 지금대로 자동이다.
   가로(㉗)는 열의 폭을 정하고 이쪽은 행의 높이를 정한다.

     높이(n) = (100% - 319px) / 12 * n + (n - 1) * 29px      319 = 11 × 29

   100% 는 .bd 높이다. 백분율로 쓰는 이유 — .sim 판면은 본문 시작이 100u 라
   .bd 높이가 1358px 이고 실행계획서는 1316px 다. 절대값을 박으면 어긋난다.

   실무확인 띠(.foot)도 같은 규칙을 탄다. margin-top:auto 는 그대로 두어
   칸 수를 안 준 면에서는 여전히 바닥에 붙는다.
   ──────────────────────────────────────────────────────────── */
.page .bd > .row[data-h],
.page .bd > .foot[data-h]{
  flex:0 0 calc((100% - 319px) / 12 * var(--h) + (var(--h) - 1) * 29px)!important;
}
```

**`[data-h]` 로 거른다.** 셀렉터에 속성을 요구해야 `--h` 없는 행에 규칙이 안 걸린다. `var(--h)` 만으로 거르면 값이 없을 때 선언 전체가 무효가 되어 `flex` 가 초기값으로 떨어진다.

### 2-2. `render/index.js` · `renderRow`

```js
function renderRow(row, { 채움, ri = 0 }) {
  // 세로 칸을 준 행은 그 높이로 고정한다. 고정 행에는 채움(.g)을 주지 않는다
  const 높이 = Number.isInteger(row.높이) ? row.높이 : null;
  const g = (채움 && !높이) ? ' g' : '';
  const h = 높이 ? ` data-h="${높이}" style="--h:${높이}"` : '';
  return `<div class="row${g}"${h}>\n` +
    (row.열 ?? []).map((c, ci) => renderCol(c, ci, ri)).join('\n') + '\n</div>';
}
```

**고정 행에 `.g` 를 주지 않는 이유** — `.row.g{flex:1}` 이 고정 높이와 부딪힌다. 마지막 행에 칸 수를 주면 그 높이로 서고 아래에 여백이 남는다. 그것이 의도다.

### 2-3. `render/index.js` · `renderFoot`

```js
function renderFoot(항목, 높이) {
  if (!항목?.length) return '';
  const h = Number.isInteger(높이) ? ` data-h="${높이}" style="--h:${높이}"` : '';
  return `<div class="foot"${db('head')}${h}>
  <div class="pt">
    <div class="pl">실무 확인</div>
    <ul>${항목.map((li, k) => `<li${dp(['실무확인', k])}>${inline(li)}</li>`).join('')}</ul>
  </div>
</div>`;
}
```

부르는 자리도 고친다.

```js
${renderFoot(page.실무확인, page.실무확인높이)}
```

### 2-4. 데이터 스키마 — 문서로만 남긴다

**이번 턴에 `content/**` 를 고치지 않는다.** 스키마만 정해 둔다.

```
행    { "높이": 4, "열": [ … ] }        2~12 정수 · 없으면 자동
면    { "실무확인높이": 2, … }           2~12 정수 · 없으면 자동
```

| | |
|---|---|

| ⑧ | 가로 트랙(㉗) · 격자 · 걸음 값을 건드리지 않는다 |

## §6 관문 — 통과 못 하면 보고하고 멈춘다

### 6-1. 왕복 — 값이 그대로여야 한다

```
node scripts/roundtrip.mjs content/sokcho/실행계획서.json
node scripts/roundtrip.mjs content/sokcho/사업장운영시뮬레이션.json
```

**`검사 1040개 · 불일치 0개` · `검사 600개 · 불일치 0개`.**
데이터에 `높이` 가 하나도 없으므로 렌더 결과가 지금과 같아야 한다.

### 6-2. 산출 HTML 에 `data-h` 가 없는가

```
node scripts/build.js content/sokcho/실행계획서.json --link
node scripts/build.js content/sokcho/사업장운영시뮬레이션.json --link
grep -c "data-h" out/html/실행계획서.html out/html/사업장운영시뮬레이션.html
```

**둘 다 `0`.** 아직 어느 문서도 칸 수를 안 줬으니 한 개도 나오면 안 된다.

### 6-3. `.g` 가 그대로 붙는가

```
grep -c 'class="row g"' out/html/실행계획서.html
```

**22 가 나와야 한다** — 표지를 뺀 22쪽의 마지막 행. 이 값이 줄면 `.g` 조건을 잘못 건드린 것이다.
