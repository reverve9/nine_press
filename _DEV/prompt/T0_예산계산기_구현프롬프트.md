## §0 역할

**빈 박스에 무엇이 얼마나 들어가는지를 재서 표로 낸다.**

기존 자들은 「넘쳤나」를 묻는다. 이건 **거꾸로 묻는 자**다 · 「몇 줄이 들어가나」.

```
scripts/기준선.mjs    덩이가 42 배수에 앉았나
scripts/박스재기.mjs   글이 박스를 넘쳤나
scripts/예산.mjs      ← 이 박스에 몇 줄 · 한 줄에 몇 자        새로 만든다
```

**T1 원고 규격서가 이 표 없이는 못 써진다.** 「이 박스에 몇 줄」이 규격서의 본문이다.

**이번 블록은 재기만 한다.** 렌더러 · CSS · 편집기를 건드리지 않는다.

---

## §1 작업 범위

### 1-1 `scripts/예산.mjs` 신규 · 한 파일

**`scripts/박스재기.mjs` 와 같은 꼴로 짓는다.** playwright 로 띄우고 잰다.
새 개념을 만들지 마라 · 재는 방법은 이미 그 파일에 있다.

```
node scripts/예산.mjs                  레이아웃 12 × 모드 2 전수
node scripts/예산.mjs G3 연속           한 칸만
node scripts/예산.mjs --json           기계가 읽는 꼴 · T1 규격서가 이걸 부른다
node scripts/예산.mjs --비움            §1-3 비움 중앙값만
```

### 1-2 재는 것

**박스마다 다섯 값.**

```
안폭 · 안높이      안여백 33 을 뺀 값
한 줄 글자수       24px 한국어 산문 실측 · §3-3 표본으로 잰다
총 줄 수           안높이 ÷ 42
머리가 먹는 줄      제목 1 + 머리뒤 1 = 2
출처가 먹는 줄      1
```

**요소 조합을 다 재지 마라.** 위 다섯이면 뺄셈으로 나온다.

```
문단만              총 줄 수
제목 + 문단          총 줄 수 − 2
제목 + 문단 + 출처    총 줄 수 − 3
목록                항목 하나가 1줄 · 항목 사이 0
번호목록             같다
표                  (행 수 + 헤더) 줄
```

**뺄셈이 맞는지 확인한다.** 문단만 채운 것과 제목 + 문단을 채운 것을 각각 재서
차가 정확히 2줄인지 본다. 안 맞으면 표에 실측값을 쓰고 §6 에 적는다.

### 1-3 비움 기본 높이 · 중앙값

**봉인본 39쪽에서 「비움으로 넘길 것」들의 실제 높이를 재고 중앙값을 낸다.**

```
대상   단계띠 7건 · 지도 1건       봉인본 셋 · --v3 로 그린다
산출   각 건의 높이(px) · 42 블록 수 · 중앙값
```

**이 값이 T3 변환기의 `[비움: …]` 기본 블록 수가 된다.**
사용자가 「단계띠 비움은 추후 수정 예정」이라 했다 · **지금은 중앙값 하나만 낸다.**

### 1-4 산출 형식

**사람이 읽는 표.**

```
레이아웃  모드   박스  안폭×안높이    한 줄  총 줄  머리 −  출처 −
G3       연속    1    632×1108      36     26     2       1
G3       연속    2    631×1108      36     26     2       1
G3       연속    3    632×1108      36     26     2       1
```

**`--json` 은 같은 값을 배열로 낸다.** T1 규격서가 표를 손으로 옮겨 적지 않고 이걸 부른다.

### 1-5 손대지 않는 것

```
render/index.js · render/inline.js · rules/page.css · app/ 전부
scripts/기준선.mjs · 박스재기.mjs · roundtrip.mjs · 비움.mjs · build.js
content/ 전부
```

**검사용 문안이 필요하면 `content/_check/예산.json` 을 새로 만든다.** 기존 문안을 고치지 마라.

## §3 착수 전 확정 사항

**전부 확정값이다. 사용자에게 되묻지 마라.**

### 3-1 원고가 낼 수 있는 것 · 닫혔다

**이 목록이 예산을 재는 범위다. 여기 없는 것은 재지 마라.**

```
페이지   번호 · 제목 · 모드(카피 · 연속) · 레이아웃(G1~G12)
밴드     카피(메인 · 서브) · 요지
박스     제목 · 문단 · 목록 · 번호목록 · 표 · 그림(경로만) · 출처 · 비움(무엇만)
표기     **굵게** 하나
```

**원고에서 뺀 것.** 사용자 확정이다.

```
요약     39쪽에 6건 · 편집기에서 넣는다
수치     39쪽에 4건 · 편집기에서 넣는다
빈칸     조판상의 틈 · 원고가 아는 물건이 아니다
조판 열쇠 표 폭 · 표 높이 · 그림 높이 · 안여백 · 도형 · 얹기 전부
구간 표기 색 · 크기 · 자간 셋은 편집기 · 굵기만 원고
```

**그래도 안폭 · 안높이 · 총 줄 수는 요약 · 수치와 무관하다.** 그 둘을 재지 않을 뿐이다.

### 3-2 모드 둘 · 안여백

```
모드     카피 · 연속 둘 다 잰다
안여백    33 · 문서 기본값 하나로만 잰다 · 박스별 덮어쓰기는 재지 않는다
```

### 3-3 표본 문장

**지난 세션이 한 줄 글자수를 잴 때 쓴 24px 한국어 산문 표본을 그대로 쓴다.**
`_DEV/prompt/T_원고입력층_답변.md` §2-2 가 다섯 레이아웃에서 1056자로 쟀다.

**그 표본을 스크립트 안에 상수로 박는다.** 파일에서 읽지 마라 · 재현이 안 된다.
표본이 남아 있지 않으면 봉인본 문단들을 이어 붙여 새로 만들고 · 그 값을 §6 에 적는다.

### 3-4 기대값 · 어긋나면 보고한다

**지난 세션 실측이다. 이 값과 다르면 재는 방법이 달라진 것이다.**

| 레이아웃 | 안폭 | 한 줄 글자수 |
|---|---|---|
| G1 | 2113 | 117.3 |
| G2 | 1002 | 55.6 |
| G3 | 632 | 36.4 |
| G6 | 447 | 24.6 |
| G11 넓은 쪽 | 1372 | 75.4 |

**소수점을 그대로 내지 마라.** 규격서는 「넘기지 않는 값」을 써야 한다 · **내림한다.**
`36.4 → 36자`.

### 3-5 줄 수는 두 방법으로 재서 맞대 본다

```
① 높이 ÷ 42
② Range.getClientRects().length
```

**지난 세션에서 다섯 레이아웃 전부 일치했다.** 이번에도 맞는지 확인하고 · 어긋나는 칸이
있으면 그 칸만 §6 에 적는다. **어긋난다고 고치지 마라.**

## §5 관문 · 자체 확인

### 5-1 회귀 · 아무것도 안 움직였다

```
node scripts/기준선.mjs   content/_check/판면기준.json
node scripts/박스재기.mjs content/_check/판면기준.json
```

**08-31 통과값 그대로여야 한다** · 기준선 0/205 · 박스재기 넘침 7건.
이번 블록은 렌더러를 안 건드리니 한 칸도 달라지면 안 된다.

### 5-2 전수 산출

```
node scripts/예산.mjs
```

**레이아웃 12 × 모드 2 = 24 칸이 다 나온다.** 빈 칸이 있으면 그 이유를 적는다.

### 5-3 §3-4 대조

**다섯 레이아웃 한 줄 글자수가 기대값과 맞는지 칸마다 통과 · 불통과를 적는다.**

### 5-4 뺄셈 확인

**한 레이아웃(G3 연속)에서 실제로 채워 재 본다.**

```
문단만            총 줄 수와 같은가
제목 + 문단        총 줄 수 − 2 인가
제목 + 문단 + 출처  총 줄 수 − 3 인가
```

### 5-5 비움 중앙값

```
node scripts/예산.mjs --비움
```

**단계띠 7 · 지도 1 각각의 높이와 42 블록 수 · 중앙값이 나온다.**

### 5-6 `--json`

**표와 같은 값인지 눈으로 한 번 대조한다.**
