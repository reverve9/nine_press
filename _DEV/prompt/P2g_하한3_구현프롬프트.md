## §0 역할

**열 하나의 하한을 4칸에서 3칸으로 내린다.**

하한 4칸이면 `4 × 4 = 16 > 12` 라 **4열 구성이 원천 봉쇄된다.** 3칸이면 `3+3+3+3 = 12` 로 열린다.

**아침 판정을 뒤집는 것이 아니다.** 「3칸에는 전용 변형이 필요하다」는 여전히 맞고 그것은 P5 소관이다. 다만 **하한으로 막을 일이 아니다** — 3칸에 표를 넣어 무너지면 저장할 때 넘침으로 잡힌다. 도구가 미리 막으면 4열이라는 정당한 구성까지 죽는다.

**2칸은 계속 막는다.** 333px 은 목록도 한 줄에 열 자가 안 들어간다.

**이 프롬프트의 범위 밖을 건드리지 않는다.**

## §1 작업 범위 — `app/ui/Shell.jsx`

### 1-1. 끌기 제약

```
지금   이동 = Math.max(4 - 끌.왼칸, Math.min(끌.오칸 - 4, 이동));
후     이동 = Math.max(3 - 끌.왼칸, Math.min(끌.오칸 - 3, 이동));
```

주석의 「두 열 모두 하한 4칸」도 **3칸**으로 고친다.

### 1-2. 칩 목록

```
지금   {[4, 5, 6, 7, 8, 12].map((w) =>
후     {[3, 4, 5, 6, 7, 8, 12].map((w) =>
```

### 1-3. 칩 동작의 하한

`폭바꾸기` 안에서 받을 열이 하한 아래로 내려가는지 보는 자리. **`4` 를 `3` 으로.**

### 1-4. 열넣기

```
지금   왼쪽 열이 8칸 미만이면 거부 · 4칸을 떼어 새 열에 준다
후     왼쪽 열이 6칸 미만이면 거부 · 3칸을 떼어 새 열에 준다
```

거부 로그도 고친다.

```
'열을 넣으려면 지금 열이 6칸 이상이어야 한다'
```

**이러면 `12 → 9+3 → 6+3+3 → 3+3+3+3` 으로 4열까지 닿는다.**

### 1-5. 그 밖에 남은 하한 값

`app/ui/Shell.jsx` 에서 하한 4칸을 전제한 자리가 더 있는지 **전수로 훑는다.**

```
grep -n "4\b" app/ui/Shell.jsx | grep -i "칸\|폭\|하한\|w\b"
```

`renderBlock` · `renderCol` 의 **기본 칸 수 `4` 는 그대로 둔다.** 그것은 하한이 아니라 새 블록의 기본 폭이다.

### 1-6. 열빼기

**바꾸지 않는다.** 지운 칸을 인접 열에 넘기는 규칙은 하한과 무관하다.
