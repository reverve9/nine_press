## ① §3-3 표본 · 지어내지 않는다

**「표본이 남아 있지 않으면 새로 만든다」 갈래를 삭제한다.** 표본을 레포에 못 박는다.

**만드는 법 — 결정적이어야 한다**

```
1. content/sokcho/실행계획서.json 을 읽는다
2. 문단 요소의 본문 문자열만 · 문서 등장 순서대로 · 사이에 공백 하나로 이어 붙인다
   (제목 · 표 · 목록 · 출처 · 요약 제외)
3. 앞에서부터 정확히 1056자를 자른다
4. content/_check/표본.txt 로 커밋한다 (끝 줄바꿈 없이)
```

1056자에 모자라면 `content/` 아래 **제안서 계열 JSON** 을 파일명 오름차순으로 이어 붙여 채운다.
그래도 모자라면 **거기서 끊고 · 실제 길이를 §6 에 적는다.** 글자를 지어 채우지 마라.

**이후 모든 측정은 이 파일을 읽는다.** 코드 안에 문자열 상수로 박지 마라.

**§5-3 대조 기준 · 완전 일치**
표본이 고정이므로 두 번 재면 같은 값이 나와야 한다.
**허용 오차 없다. 한 칸이라도 다르면 불통과다.** ±% 기준은 필요 없어졌다.

## ② §1-3 봉인본 · T0 에서 뺀다

**예산.mjs 는 새 렌더러(`render/index.js` + `rules/page.css`)만 본다.**
v3 가지를 붙이지 마라. 한 파일에 렌더러 둘을 물리지 않는다.

근거 — 이 값은 핸드오프에 이미 **「추후 수정 예정」**으로 적힌 값이다.
한 번 쓰고 사람이 갈아 끼울 숫자에 렌더러 분기를 영구히 다는 것은 남는 장사가 아니다.

**그래서 §1-3 은 산출물이 아니라 1회 실측이다.**

```
어디서   _DEV/scratch/ 아래 임시 스크립트         커밋하지 않는다
무엇을   단계띠 7건 · 지도 1건 · 요소 하나의 바깥 껍데기 세로 픽셀
어떻게   높이 ÷ 42 = 블록 수 · 반올림
         나머지가 0 이 아닌 건이 있으면 그 사실을 §6 에 적는다
내는 것  숫자만 · §6 답변에 적는다
```

**셀렉터 · 챗이 확정했다. 찾지 마라.**

```
render/_v3/index.js:110  단계띠 → <div class="fl">  > .st > .sd/.sm
render/_v3/index.js:118  지도   → <div class="pmap"> > .pc > .pd/.pn/.px/.pf
```

`.sd/.sm` · `.pd/.pn/.px` 가 칸이라는 판단이 맞다. 띠 전체는 **`.fl`** · 지도 전체는 **`.pmap`** 이다.

**다만 재는 것은 `.fl`·`.pmap` 이 아니라 그것을 담은 `.b` 다.**
원고가 비움으로 넘기는 자리는 블록 하나이므로 껍데기까지 포함한 높이가 기본값이 된다.

**갈래가 둘이라는 것을 알고 재라** · `rules/_v3/page.css:543`

```
.sim .b:has(> .fl) · :has(> .pmap)   border:0 · padding:0    껍데기 없음
그 밖                                 블록 기본 껍데기 있음
```

7건의 분포도 확정했다 — `사업장운영시뮬레이션` 6건(`.sim`) + `홍보전략브리프` 1건(`.sim` 아님) ·
지도 1건은 `사업장운영시뮬레이션`(`.sim`). **중앙값은 `.sim` 쪽 값으로 떨어진다.**
`.sim` 값과 비-`.sim` 값이 얼마나 갈리는지 **§6 에 함께 적어라** — T1 에서 갈래를 나눌지 판정한다.

## ③ 중앙값 · 종류별로 따로

```
단계띠   7건 · 정렬해서 4번째 값        → 기본 블록 수 하나
지도     1건 · 그 값 그대로            → 기본 블록 수 하나
```

**통합 중앙값 하나는 내지 마라.** 성격이 다른 물건이고 · 원고 문법이 이미
`[비움: 단계띠]` 처럼 **종류를 적는다.** 기본값도 종류별이면 그대로 맞물린다.
지도 한 건이 단계띠 기본값을 끌어 올리는 일도 없어진다.

두 값은 T1 규격서와 T3 변환기의 기본값으로 들어간다. 사용자가 나중에 손본다.

## ④ §5-2 관문 · 24 → 78

관문 문구를 교체한다.

```
바꾸기 전   24 칸이 다 나온다
바꾼 뒤     표가 정확히 78행이다 · (레이아웃 · 박스 · 모드) 조합이 하나도 빠지지 않는다
```

근거 — 레이아웃 12 의 **박스 수 합이 39** (G9 하나가 6) · 모드 2 → 39 × 2 = **78**.
`24` 는 레이아웃 × 모드 조합 수일 뿐이고 · 표의 행 수가 아니다.

**검사** — 행 수 `=== 78` 이고 · `(레이아웃, 박스번호, 모드)` 키가 중복 없이 78개.
둘 중 하나라도 어긋나면 불통과.

## ⑤ §1-1 · playwright 를 한 자리로 몰아라

지적이 맞다. **다섯 값 중 넷은 브라우저가 필요 없다.**

```
영역() 순수 호출     안폭 · 안높이 · 총 줄 수 · 박스 목록      브라우저 안 띄운다
playwright          한 줄 글자수                            이것 하나뿐
```

`--json` 78행은 **브라우저 없이** 나와야 한다. 한 줄 글자수 열만 playwright 경로를 탄다.
이 갈림을 §1-1 에 한 줄로 박아라. 구현이 얇아지고 · 회귀할 자리가 하나로 준다.

## ⑥ §5-4 · 재는 표본과 채우는 문안을 가른다

```
재기용   content/_check/표본.txt · 1056자 전부
        넘쳐도 된다 — 넘쳐야 줄바꿈 지점이 나온다

채움용   같은 파일 앞에서 (기대 줄 수 × 한 줄 글자수 − 20자) 만큼 자른다
        별도 파일을 만들지 마라 · 자르는 규칙만 코드에 둔다
```

**뺄셈 확인(−2 · −3)은 채움용으로 한다.** 재기용 1056자는 G3(26줄 · ≈936자)를 넘겨서
채움 검사에 쓰면 항상 넘침으로 떨어진다.
