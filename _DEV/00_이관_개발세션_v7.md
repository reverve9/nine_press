## §3 작업 방식 · **이번 세션에서 바뀌었다**

**옛 방식** · 사용자가 `_DEV/prompt/<단계>_구현프롬프트.md` 를 쓰면 그대로 수행.
**새 방식** · 사용자 지시 그대로다.

> 프롬프트 초안을 검토 받을 일은 없고 로컬서버 내가 돌리고 있으니까
> 바로바로 진행하고 나한테 확인 받으면 되고 단 페이즈는 잘 나눠서 가자

| | 규칙 |
|---|---|
| ① | **프롬프트 왕복을 하지 않는다.** 바로 넣고 사용자에게 눈 검사를 받는다 |
| ② | **페이즈를 잘게 나눈다.** 한 번에 하나씩 · 각각 눈으로 판정 가능하게 |
| ③ | **무엇을 볼지 정확히 짚어 준다.** 「몇 면 어디가 어떻게 보이면 통과」까지 |
| ④ | **`git` 을 직접 쓰지 않는다.** `sh scripts/save.sh "메시지" <경로들>` 만 쓴다 |
| ⑤ | **`next build` 를 돌리지 않는다** |
| ⑥ | **dev 서버에 붙지 않는다.** 눈 검사는 사용자가 한다 |
| ⑦ | 표기 · `—` 를 쓰지 않는다. 구분자는 `·` 와 `\|`. 분량은 「쪽」으로 센다 |
| ⑧ | **관문을 통과해야 커밋한다.** §1 의 넷 |

**설계가 논의 중에 바뀐다.** 이번 세션에도 네 번 바뀌었다(§6). 바뀌면 설계 문서를 고치고 이유를 남긴다.

### 4-1. 다음 할 일 · `N-글자 b` 머리 계층 뒤 위계

**사용자가 제기한 문제다.**

> 라벨과 본문 첫 행의 행간이 같으면 가독성이 떨어지지

지금 세로 리듬에 위계가 없다. **제목 → 요약 → 본문 → 본문이 전부 42 로 같다.**

간격에 쓸 수 있는 값은 **0 또는 42 뿐이다** · 21 은 문단마다 홀짝으로 엇갈린다.
그래서 판단은 「어디에 한 칸을 쓸 것인가」다. 치르는 값은 자리당 본문 한 줄이다.

**주의 · 비교본 셋을 만들어 뒀는데 그건 계층 재배정 전 값이다.**
`out/html/_위계_*.html` 은 폐기하고 **29px 박스 타이틀 기준으로 다시 만들어야 한다.**

```
자리당 본문 줄  G1 21줄 · G3 21줄 · G9 9줄
간격 없음      제목1 + 요약1 + 본문 19 / 19 / 7
제목 뒤 42     제목1 + 빈1 + 요약1 + 본문 18 / 18 / 6
```

**G9(9줄)에서 손실이 크다.** 작은 자리를 기준으로 판단한다.

## §5 관문과 도구

```sh
node scripts/기준선.mjs [문안.json]      42 격자 전수 검사 · 어긋나면 종료 코드 1
node scripts/roundtrip.mjs <문안> [--v3] 제자리 편집 왕복 검사
```

| 깃발 | 뜻 |
|---|---|
| `--v3` | **봉인한 12칸 트랙 렌더러**로 그린다 · 옛 문안 39쪽 전용 · `render/_v3/봉인.md` |

**개발 서버에서 자를 보려면** 문안에 `"기준선": true` 를 넣는다.
`content/_check/판면기준.json` 에는 이미 들어 있다.

| | 무엇 | 결론 |
|---|---|---|
| ① | **「격자 말고 행마다 상하 패딩으로 하면 안 되나」** | 기계적으로 **같은 물건**이다(`line-height` 가 곧 상하 패딩). 비율로 두면 옛 상태로 돌아간다(154/205 어긋남). **다만 한 줄이 보장되는 계층은 패딩이 낫다** → 라벨만 패딩 |
| ② | **「라벨과 본문 첫 행 간격이 같으면 가독성이 떨어진다」** | 맞다. **아직 안 고쳤다** · `N-글자 b` |

**②는 아직 열려 있다. 다음 세션이 닫는다.**

## §7 함정

| | 무엇 |
|---|---|
| ① | **`roundtrip` · `build` 가 옛 문안에서 깨진다.** `--v3` 를 붙인다. 안 붙이면 `구성에 띠가 없다` |
| ② | **`save.sh` 에 한글 파일 경로를 못 넘긴다.** macOS 가 NFD 자모 분해형으로 저장해 NFC 문자열과 안 맞는다. **에러 없이 「바뀐 것 없음」만 찍는다.** 상위 디렉터리 이름(`content` · `rules` · `_DEV`)으로 넘긴다 |
| ③ | **문안 파일을 밖에서 고치면 개발 서버를 재시작해야 반영된다** |
| ④ | **「제목」이 두 뜻이다.** `면.제목` 은 헤더 밴드(폭 2179 · 안 접힌다) · `자리.제목` 은 자리 안이다. **섞어 재서 틀린 값을 한 번 냈다** · 면 제목 39 · 블록 제목 6 이 맞다 |
| ⑤ | **`--문단사이` 는 0 또는 42 만 쓴다.** 21 은 홀짝으로 엇갈린다 |
| ⑥ | **라벨(`.lb`)은 한 줄 전제다.** 두 줄이면 70 이 되어 격자가 깨진다 |
| ⑦ | **메인카피는 한 줄이다.** 두 줄이면 카피 존 156 을 57 넘친다 · 64px 에 **34자** 한계 |
| ⑧ | **논지 밴드는 여유가 0 이다.** 45 × 1.2 = 54 로 딱 맞는다 |
| ⑨ | **가로 `split()` 은 고치지 않는다.** 「키노트 세팅 그대로다」가 붙어 있다. 세로 `rows()` 에는 안 붙어 있어 이번에 스냅했다 |
| ⑩ | **검사 도구를 먼저 의심한다.** 이번에 두 번 · 자리별 여백을 안 읽어 거짓 어긋남 · 새 계층을 안 세어 덩이 누락 |
| ⑪ | **크롬 확장이 안 붙는다.** 브라우저 교차검사는 **Playwright 로 한다** · 레포에 이미 있다 |
