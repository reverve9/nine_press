**최대는 없다.** 2560 × 1440 · 1170 × 2532 도 그대로 들어간다.

### 2-1. `mo` 뷰포트 근거

**390 × 845 는 iPhone 논리 해상도 390 × 844 와 같다.** 9 : 19.5 정확히 떨어진다. 414 × 897 (@2x = 828 × 1794) 도 같은 비율이라 대체 가능하다.

### 2-2. `pc` — **뷰포트만 찍는다**

주소창 · 탭 · 북마크바가 들어가면 지면에서 화면이 아니라 브라우저로 읽힌다. 창 전체 캡처 금지.

### 2-3. playwright 로 뜬다면

```
await page.setViewportSize({ width: 1920, height: 1080 });          // pc
const ctx = await browser.newContext({ viewport: { width: 390, height: 845 }, deviceScaleFactor: 2 });  // mo
await page.screenshot({ path: 'A1_접수목록.png' });                  // fullPage 금지 — 뷰포트만
```

**`fullPage: true` 를 쓰지 않는다.** 세로로 늘어난 그림이 16 : 9 자리에 들어가면 양옆이 비거나 잘린다.

## 8. ⚠ 캡처가 나와도 **아직 지면에 넣을 경로가 없다**

`render/index.js` 의 `자리()` 는 지금 **이름만** 받는다.

```js
["pc", "접수 목록 화면"]      → <div class="sh pc"><span>접수 목록 화면</span></div>
```

파일 경로를 넣을 키가 없다. 개발계획 v2 §4 의 **P4(이미지 — 경로 · 맞춤 · 초점)** 가 그것을 여는 페이즈이고 **아직 안 열렸다.**

| | 갈래 |
|---|---|
| **㉠** | **P4 를 앞당긴다** — 캡처가 나오는 시점에 맞춘다 |
| **㉡** | 캡처만 먼저 모아 두고 P2.5-b · P3 을 예정대로 돈다 |
| **㉢** | 자리에 `경로` 키만 먼저 열고(렌더러 3줄) 맞춤 · 초점은 P4 로 미룬다 |

**㉢ 이 가장 싸다.** `자리(["pc","이름","경로"])` 로 배열을 하나 늘리고 `<img>` 를 얹으면 되고, 맞춤·초점 UI 없이도 지면은 완성된다. 다만 개발계획 v2 §1 「한 번 쓰고 마는 값은 닫는다」에 걸리지 않는지 확인이 필요하다 — **경로는 §1-1 에서 이미 「연다」쪽이다.**
