## §1 세우기

**이 머신에서는 이미 서 있다.** 새 머신에서만 아래를 따른다.

```sh
git clone git@github.com:reverve9/nine_press.git
cd nine_press
npm install
npx playwright install chromium        # 관문 셋이 이걸 쓴다
```

**SSH 키를 먼저 세운다.** 없으면 `save.sh` 가 커밋만 하고 푸시에서 멈춘다.

```sh
ssh-keygen -t ed25519 -C "reverve9@naver.com · <머신이름>" -f ~/.ssh/id_ed25519 -N ""
ssh-add --apple-use-keychain ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub          # GitHub → Settings → SSH and GPG keys → New SSH key
ssh -T git@github.com              # "Hi reverve9!" 가 나오면 선다
```

`~/.ssh/config` 에 `Host github.com` · `IdentityFile ~/.ssh/id_ed25519` · `IdentitiesOnly yes` ·
`AddKeysToAgent yes` · `UseKeychain yes`.

**공개키 등록만 사람이 한다.** 브라우저에 로그인만 돼 있으면 챗 세션이 폼을 채워 등록할 수 있다 ·
**비밀번호 입력은 챗 세션이 못 한다.**

**폰트는 안 받아도 된다.** `assets/fonts/*.woff2` 14개가 레포에 있다.

```sh
npm run dev        # http://localhost:4400 · 사용자가 띄운다
```

## §2 작업 방식

**사용자 지시 그대로다.**

> 프롬프트 초안을 검토 받을 일은 없고 로컬서버 내가 돌리고 있으니까
> 바로바로 진행하고 나한테 확인 받으면 되고 단 페이즈는 잘 나눠서 가자

| | 규칙 |
|---|---|
| ① | **프롬프트 왕복을 하지 않는다.** 바로 넣고 사용자에게 눈 검사를 받는다 |
| ② | **페이즈를 잘게 나눈다.** 한 번에 하나씩 · 각각 눈으로 판정 가능하게 |
| ③ | **무엇을 볼지 정확히 짚어 준다.** 「몇 면 어디가 어떻게 보이면 통과」까지 |
| ④ | **`git` 을 직접 쓰지 않는다.** `sh scripts/save.sh "메시지" <경로들>` 만 쓴다 |
| ⑤ | **`next build` 를 돌리지 않는다** |
| ⑥ | **dev 서버에 붙지 않는다.** 눈 검사는 사용자가 한다 |
| ⑦ | 표기 · `—` 를 쓰지 않는다. 구분자는 `·` 와 `\|`. 분량은 「쪽」으로 센다 |
| ⑧ | **관문을 통과해야 커밋한다** · §4 |
| ⑨ | **`_DEV` 를 통째로 넘기지 않는다.** `_DEV/*.md` 글로브로 넘긴다 · 함정 ⑮ |

**설계가 논의 중에 바뀐다.** 바뀌면 설계 문서를 고치고 이유를 남긴다.
**판단은 추론이 아니라 실측으로 한다** — 이번 세션의 결정 대부분이 재 보고 뒤집혔다.

### 5-1. 사이드패널

```
[기준선]  [블록]                      .wrap 에 bl · dbg 클래스만 껐다 켠다
배율  [맞춤] [25%] [50%] [100%]        못박으면 키노트와 같은 %로 견준다
자리 N / M  [비움]  + 메모 칸          판면에서 자리를 누르면 뜬다
```

**전부 산출물에 안 나간다.** 판면을 다시 그리지 않으므로 제자리 편집 중에 눌러도 커서가 안 날아간다.

**자리 고르기** · 글자를 누르면 글자 편집 · **빈 곳을 누르면 자리 고르기**로 갈린다.

## §7 함정 · 스물넷

| | 무엇 |
|---|---|
| ① | **`roundtrip` · `build` 가 옛 문안에서 깨진다.** `--v3` 를 붙인다 |
| ② | **`save.sh` 에 한글 파일 경로를 못 넘긴다.** macOS NFD 와 NFC 가 안 맞아 **에러 없이 「바뀐 것 없음」만 찍는다.** `_DEV/*.md` 처럼 **글로브**로 넘기면 셸이 디스크 바이트로 펼쳐 줘서 풀린다 |
| ③ | **문안 파일을 밖에서 고치면 개발 서버를 재시작해야 반영된다** |
| ④ | **「제목」이 두 뜻이다.** `면.제목` 은 헤더 밴드 · `자리.제목` 은 자리 안 |
| ⑤ | **`--문단사이` · `--머리뒤` 는 0 또는 42 만.** 21 은 홀짝으로 엇갈린다 |
| ⑥ | **라벨(`.lb`)은 한 줄 전제다.** 두 줄이면 70 이 되어 격자가 깨진다 |
| ⑦ | **메인카피는 한 줄이다.** 64px 에 34자 한계 |
| ⑧ | **논지 밴드는 여유가 0 이다.** 45 × 1.2 = 54 |
| ⑨ | **가로 `split()` 은 고치지 않는다.** 「키노트 세팅 그대로다」가 붙어 있다 |
| ⑩ | **검사 도구를 먼저 의심한다.** 이번 세션에도 측정 스크립트가 두 번 틀렸다 |
| ⑪ | **크롬 확장은 붙는다.** 이 머신에서 GitHub 폼 작성까지 됐다 |
| ⑫ | **비교본은 문안을 예산에 꽉 채운다.** 안 채우면 안마다 「안 넘침」이 나와 **치르는 값이 안 보인다** |
| ⑬ | **한 줄 글자 수를 `폭÷24` 로 어림하면 30% 적다.** 실측 632px 에 34자 · 2113px 에 107자. 설계 §5-2 표는 일부러 보수적이지 틀린 게 아니다 |
| ⑭ | **임시 스크립트를 `/tmp` 에 두면 `playwright` 를 못 찾는다.** ESM 해석이 파일 위치 기준이다 · **`out/` 에 둔다** |
| ⑮ | **`save.sh` 에 `_DEV` 를 통째로 넘기면 안 된다.** `.key` 꾸러미 214개 + 75MB PDF 가 딸려 들어가 레포가 **12.9MB → 231MB** 가 됐다. `.gitignore` 로 막아 뒀지만 **글로브로 넘기는 것이 정답** |
| ⑯ | **`save.sh` 는 푸시가 막혀도 커밋은 한다.** 커밋은 살아 있으니 키를 세운 뒤 `git push` 만 |
| ⑰ | **`display:inline-block` 은 제 높이로 줄 상자를 밀어 올린다.** 배지가 42 → 44 로 만들어 그 줄만 밀렸다 · **제 행간을 함께 준다** |
| ⑱ | **한 줄에 크기가 다른 글자를 섞으면 줄 상자가 `line-height` 보다 커진다.** 기준선 합집합 때문이다 · 값 52 + 단위 26 에서 84 → 97 · **`height` 로 못박고 정렬은 flex 에** |
| ⑲ | **문단 안 줄바꿈은 된다** · Enter → `<br>` → `\n`. **못 하는 건 문단을 나누고 합치는 것**(B 페이즈) |
| ⑳ | **`바꾸기(fn)` 의 `fn` 이 `false` 를 돌려주면 「취소」다.** 짧은 화살표로 쓰면 반환값이 새어 나간다 · **중괄호로 감싼다** |
| ㉑ | **swc `transform` 통과 = 문법 통과가 아니다.** **중복 선언을 안 잡는다** · webpack 이 잡아 「빌드 에러」로 뜬다 · §4 의 `node --check` 를 돌린다 |
| ㉒ | **`Shell.jsx` 에 옛 12칸 트랙 이름이 살아 있다** · `블록` · `행` · `열` · `새블록`. 새 이름 짓기 전에 `grep -n` 한다 |
| ㉓ | **골격 체계에서 옛 구조 편집 패널은 죽어 있다.** 새 렌더러가 `data-b` 를 안 낸다. 「칸 수」 「배경」 「+ 블록」은 안 뜬다 |
| ㉔ | **렌더러 오류가 앱을 죽였다.** 이제 `오류판()` 이 판 자리에 메시지를 그린다. 옛 문안 넷을 골라도 앱이 산다 |

## §8 판이 키노트와 같은 좌표계다 · **이번 세션의 발견**

```
_DEV/제안서(200dpi).pdf   MediaBox 0 0 2339 1654 · Creator Keynote · 29면
우리 판                    2339 × 1654 · 200dpi A4
                           297÷25.4×200 = 2338.6 → 2339
                           210÷25.4×200 = 1653.5 → 1654
```

**그래서 `scripts/비움.mjs` 가 뽑은 좌표를 키노트 도형에 그대로 넣으면 자리가 맞는다.**
비움 체계가 서는 근거가 이것이다 · 설계 §5-11.

**PDF 는 도구 없이 뜯을 수 있다.** 내용 스트림을 `zlib` 로 풀고 `Tf` · `Tm` 을 읽으면 된다.
Keynote 는 `/F 1 Tf` + `21 0 0 21 x y Tm` 꼴이라 **Tm 이 크기를 나른다.**

**실물 제안서의 글자 크기** · 본문 **21 · 22 · 23** · 라벨 20 · 페이지타이틀 40 · 강조 50 · 카피 65.
세팅표(우리 값)와 대부분 1~2px 안쪽이고 **라벨 20 은 정확히 맞는다.**
**본문만 갈린다** — 우리는 24 다. 사용자 판정 · **「PDF 보다 작으면 안 되지만 크면 상관없다」 → 24 유지.**
