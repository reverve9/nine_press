## §1 목적

**키노트를 쓰지 않고 제안서 · 보고서 · 내부 문서를 쉽게 만든다.**

목적이 둘로 갈린다. 우선순위 판단은 언제나 이 둘로 되돌아온다.

```
「키노트 없이」  =  판면 품질      →  조판 엔진이 담보한다
「쉽게」        =  자동 초안 + 편집기  →  본론은 이쪽이다
```

**JSON 을 손으로 고치는 것은 「쉽게」가 아니다.** 편집기는 곁가지가 아니라 목적의 절반이다.

## §2 흐름 · 원고에서 PDF 까지

```
챗 세션                      원고 규격서를 읽은 클로드가 .md 를 낸다
    ↓ .md
템플릿 + 변환기               문서 종류별 템플릿에 얹어 면 JSON 을 만든다
    ↓ 면 JSON  (파생물)
편집기                        사람이 내용을 고친다
    ↓
렌더러 → HTML → PDF
```

### 2-1. 원본이 바뀐다

v1 README 는 「`content/` 가 유일 원본」이라 못박았다. **그 전제가 바뀐다.**

```
옛   [ 면 JSON · 문안과 조판이 한 몸 ]  →  렌더러        ← 사람이 손으로 쓴다
새   [ 원고 ]  →  [ 템플릿 + 변환기 ]  →  [ 면 JSON ]     ← 면 JSON 이 파생물로 내려간다
```

### 2-2. 클로드가 골격까지 지정한다

**일을 이렇게 가른다.**

| | 누가 | 무엇 |
|---|---|---|
| 콘텐츠 판단 | **클로드** | 「이 면은 3열이 맞다」 · 골격 지정 · 자리 배열 · 분량 준수 |
| 조판 계산 | **렌더러** | 「3열 경계는 698 · 697 · 698」 · 정수 분할 · 좌표 |

**검사기는 이미 있다.** N1 렌더러가 「자리 개수가 골격과 다르면 오류를 던지고 멈춘다」는 계약을 갖고 있다. 클로드가 골격을 지정하면 그 계약이 곧 검증기다.

그래서 **자동 배치기가 「변환기」로 내려간다.** 마크다운 파싱 + 계약 검증이 전부다.

## §4 설계 확정 · 넷

### 4-1. 골격 열둘 · 고르는 방식

**폭을 끌어 맞추는 대신 골격을 고른다.** 자유도를 줄여야 「쉽게」가 나온다.

```
G1  전면          G2  좌우 둘        G3  3열           G4  좌1:우2
G5  상1:하2       G6  4열           G7  2×2          G8  상3열:하전면
G9  3열·박스 둘    G10 3열·2·1·2     G11 2열 폭2:1     G12 2열 폭1:2
```

### 4-2. 배경 모델 · **표와 도형은 배경이다**

**텍스트 블록이 먼저 있고 · 표 선과 박스는 그 밑에 깔리는 배경이다.**

```
아님   박스 안에 텍스트를 넣는다 · 표 안에 텍스트를 넣는다
맞음   텍스트를 놓고 · 그 밑에 표 선과 박스를 그린다
```

텍스트 블록은 **표 선 두께와 박스 안쪽 여백까지 감안해** 만들어진다.

**이 개념이 푸는 것.** 폐기된 `_legacy/v3/rules/page.css` 455줄에 실패가 주석으로 남아 있다.

```
⑬ 표가 블록 높이를 채운다 · 밀도 md (v4)
   표 하나로 면을 채우는 구성에서, 남는 높이를 행이 나눠 갖게 한다.
   밀도를 손으로 맞추면 문안이 한 글자만 바뀌어도 다시 맞춰야 한다.
```

```
옛   텍스트가 늘어난다 → 표가 따라 늘어난다 → 밀도를 손으로 다시 맞춘다
새   격자가 먼저 확정된다 → 텍스트는 그 예산 안에서 쓰인다 → 아무것도 안 움직인다
```

**밀도 `cp` · `md` · `xs` · `fit` 여덟 조합이 폐기된다.** 고를 것이 없어진다.

**N2 프롬프트가 이미 같은 축이다.** 「도형 속성을 `.bx` 자체에 붙인다 · 래퍼 `div` 를 만들지 마라」. 도형은 컨테이너가 아니라 배경이다. 표를 같은 층으로 내리면 **N2 와 표가 한 갈래가 된다.**

**목록은 배경 대상이 아니다.** 실측으로 갈렸다 · §5-3.

### 4-3. 기준선 격자 42px

**세로 치수를 전부 42 의 배수로 못박는다.**

```
기준선 = 42px   (본문 24px × 행간 1.75)

본문 한 줄              42
표 행 높이 · 셀 높이     42 의 배수
라벨 · 제목이 먹는 높이   42 의 배수
```

**결과.** 표 안 글줄과 표 밖 글줄이 가로로 맞는다. **박스 안 정렬이 「맞추는 일」이 아니라 「어긋날 수 없는 상태」가 된다.**

**표 행 높이 규칙.**

```
행 높이 = ⌊ (자리 가용 높이 ÷ 칸 수) ÷ 42 ⌋ × 42        칸 수는 머리행 포함
남는 높이는 표를 자리 안에서 세로 가운데로 민다
```

**세로 분할도 스냅한다.** `rows()` 가 「영역 높이 + 거터」를 42 의 배수로 맞춘다.
안 그러면 박스 둘인 열이 **5px** · 띠 둘인 골격이 **18px** 어긋난다(G4 G5 G7 G8 G9 G10 여섯).
가로 `split()` 은 안 건드린다 — 거기엔 「키노트 세팅 그대로다. 고치지 않는다」가 걸려 있다.

**파생 조건.** 글자 계층 9 를 정할 때 **계층마다 행 높이를 42 의 정수배(또는 반배 21)로** 잡아야 한다. 지금 값은 안 맞는다.

```
라벨 20 × 1.4 = 28 · 제목 29 × 1.35 = 39.15
라벨+제목이 먹는 높이 = 28 + 12 + 39 + 14 = 93          42 의 배수가 아니다
```

### 4-4. 세로 스냅 · 가로 자유

조정을 열되 기준선을 깨뜨리지 않는 경계다.

| | 무엇 | 어떻게 | 왜 |
|---|---|---|---|
| **세로** | 글자 크기 · 행간 | **스냅** · 계층 9 중 고르기 · 행간은 42 배수 | 자유로 열면 기준선이 깨진다 |
| **가로** | 자간 · 셀 너비 | **자유** · 연속 조절 | 기준선과 무관하다 |
| **셀 높이** | | **42 단위로 조절** · 한 칸 늘리면 이웃이 준다 | 격자 합이 자리를 계속 채운다 |

**「자유 조판」이 아니라 「기준선 위에서 고르기」다.** 어긋난 조판을 만들 방법 자체가 없어진다.

**예산은 안 깨진다.** 두 단계가 갈려 있다.

```
원고 규격서   기본값 기준 예산을 말한다     클로드가 읽는다 · 생성 단계
편집기       기본값을 벗어나는 조정        사람이 만진다 · 수정 단계
```

### 5-5. 계층 오배정 · **N1 이 두 칸 밀려 물렸다**

키노트 세팅 §5 계층표가 정본이다.

```
메인카피        64  800          박스 타이틀     29  700
서브디스크립션    39  400          요약문         26  400
타이틀 · 논지    45  800          본문           24  400 · 행간 1.75
페이지타이틀     41  800          라벨 · 출처 · 배지 20  700/400 · 자간 +180
                                강조 수치       52  700
```

**「라벨」은 계층 이름이지 역할 이름이 아니다.** 표에서 출처 · 배지와 한 묶음이고 자간이 +180 이다.
눈썹글씨 · 꼬리표 처리이지 제목 처리가 아니다.

| JSON 열쇠 | N1 이 물린 계층 | 실제 내용 | **맞는 계층** |
|---|---|---|---|
| `자리.라벨` | 라벨 20 · 회색 · 자간 +180 | 「심사 기준」 「동의 항목」 **147개** | **박스 타이틀 29 · 700 · 남색** |
| `자리.제목` | 박스 타이틀 29 · 남색 | 「대중 인지도보다 당원 접촉이 앞선다」 **6개** | **요약문 26 · 400** |
| `자리.문단` | 본문 24 | | 본문 24 · 맞다 |
| 없음 | | 출처 · 배지 | 라벨 20 · 회색 |

**박스 타이틀 147개가 20px 회색 눈썹글씨로 찍히고 있었다.**

**밴드 계층 넷은 격자 밖이다.** 메인카피 · 서브디스크립션 · 논지 · 페이지타이틀은
카피 존(156) · 논지 존(54) · 헤더(65)에 얹히고 그 밴드 높이가 고정이라 42 배수를 안 따진다.
**자리 안 계층 다섯만** 42 격자를 지킨다 · 박스 타이틀 · 요약문 · 본문 · 라벨 · 강조 수치.

**열쇠 이름을 뜻에 맞게 바꾼다.**

```
옛   자리.라벨 · 자리.제목 · 자리.문단
새   자리.제목(박스 타이틀) · 자리.요약 · 자리.문단 · 자리.출처
```

39쪽은 어차피 `N-이관` 에서 골격 체계로 변환하므로 그때 같이 바꾼다. 값이 안 든다.

### 5-6. 머리 뒤 위계 간격 · **머리 끝에 한 칸**

자리 안은 덩이가 둘이다 · **머리(제목 + 요약)** 와 **몸(문단들)**.
제목 29 남색과 요약 26 먹은 크기 차가 3px 뿐이라 **붙여야 한 덩이로 읽힌다.**
반대로 요약과 본문 첫 줄이 같은 42 간격이면 **요약이 본문의 첫 문장처럼 읽힌다.**

쓸 수 있는 값은 0 또는 42 뿐이다(§9 ⑧). 그래서 물음은 「어디에 한 칸을 쓸 것인가」였다.

| 안 | 제목 뒤 | 요약 뒤 | 값 | 판정 |
|---|---|---|---|---|
| A 없음 | 0 | 0 | 0줄 | 머리와 몸이 한 덩이로 뭉친다 · **사용자가 제기한 문제** |
| B 제목 뒤 | 42 | 0 | 1줄 | **더 나쁘다** · 요약이 본문에 붙어 첫 문장처럼 읽힌다 |
| **C 요약 뒤** | 0 | 42 | 1줄 | **채택** · 머리 한 덩이 · 몸 한 덩이 |
| D 둘 다 | 42 | 42 | 2줄 | 한 몸인 제목과 요약을 갈라 놓고 값만 두 배 |

**`--머리뒤:42px`** · `.bt + .bd` 와 `.sm + .bd` 에 건다. `.bt + .sm` 은 0 이다.
제목만 있고 요약이 없는 자리도 같은 규칙이 선다 · 머리가 끝나면 한 칸.

**출처(`.lb`) 앞 간격은 아직 0 이다.** 라벨 자체가 상하 패딩 7 을 갖고 있어 붙어 보이지는
않는다. 본문 끝과 출처 사이에도 한 칸이 필요한지는 **표가 들어온 뒤(N-배경) 다시 본다** · §8 6.

### 5-7. 목록 · **항목 사이는 0**

실물 69건 · 항목 2~8개(3~6이 흔하다) · 합 399개다.

**항목마다 42 를 더 주면 목록 하나가 자리를 통째로 먹는다.** 여섯 항목이면 6줄이 11줄이 되고
G9(9줄)에는 아예 안 들어간다. 그래서 **항목 사이는 0** 이고 · 가르는 일은 마커가 맡는다.

```
.ls li   font 24 · line-height 42 · padding-left 30      항목 하나 = 한 줄 42
.ls li:before   "•" 를 left 6 에 절대 배치               매달린 들여쓰기
```

**매달린 들여쓰기가 핵심이다.** 두 줄짜리 항목의 둘째 줄이 마커가 아니라 글자에 맞춰 앉아
어디서 끊겼는지가 보인다. 가로 치수라 42 와 무관하다 · §4-4 「가로 자유」.

**목록 앞뒤 간격은 문단과 같은 규칙이다.** 머리 뒤 42 · 몸 안의 덩이 사이 42.

```
.bt + .ls · .sm + .ls          --머리뒤 42
.bd + .ls · .ls + .bd · .ls + .ls   --문단사이 42
```

**항목 하나가 편집 잎사귀 하나다.** `data-p` 는 `<li>` 에 붙는다 · 왕복 검사가 그대로 훑는다.

**번호목록도 같은 규칙이다.** 실물 11건 · 항목 5~8개. 마커만 **원형 배지**로 바뀐다.

```
.ol li          padding-left 42 = 배지 24 + 사이 18
.ol li:before   counter(ol) · 절대 배치 · 24 × 24 원 · top 9
```

**배지는 절대 배치라 줄 상자에 안 낀다** — §5-8 과 반대 경우다. 세로 중심이 딱 떨어진다 ·
줄 상자 42 · 배지 24 → `(42 − 24) / 2 = 9`. v3 은 행간이 비율이라 이 값을 못 구하고
눈대중으로 **두 번 틀렸다**(`rules/_v3/page.css` ⑭ 주석). **42 격자가 그 문제를 없앴다.**
배지는 두 자리(12)까지 받는다 · 실측으로 확인했다.

**빈 항목은 안 낸다.** 글자를 지우면 마커만 유령으로 남았다. 두 군데를 함께 고쳤다.

```
렌더러    빈 항목 · 빈 문단은 아예 안 낸다      인덱스는 원본 그대로 · data-p 가 안 어긋난다
편집기    배열 잎사귀를 비우면 배열에서 뺀다     ⌘Z 로 되살아난다
```

**「비운다 = 지운다」가 목록에서만 되는 구조 편집이다.** 문단을 나누고 합치는 것은
아직 안 된다 · B 페이즈 · §8 7.

### 5-8. 인라인 배지가 격자를 깬다 · **고쳤다**

`{TBD}` 배지(`.tbd`)는 `display:inline-block` 이라 **제 높이로 줄 상자를 밀어 올린다.**
행간 42 를 그대로 물려받으면 상자가 42 + 테두리 2 = **44** 가 되어 그 줄만 2px 밀린다.

```
목록 검사에서 실측  ul 높이 170 · 212 · 298     42 배수가 아니다
배지에 line-height:24 를 주고 다시  168 · 210 · 294
```

**배지가 든 줄은 문단이든 목록이든 어디서나 깨졌다.** 목록을 넣다가 드러났을 뿐이다.
**앞으로 `inline-block` 을 새로 만들 때마다 제 행간을 함께 준다** · §9 ⑪.

### 5-9. 본문 크기는 변수 하나다 · 배지는 떼어 놨다

```
--본문:24px      .bd · .ls li · .ol li 셋이 이 하나를 쓴다
.tbd             20px 고정 · --본문 을 안 따라간다
```

**배지 크기를 `.85em` 에서 20 고정으로 바꿨다.** 두 가지 이유다.

```
① 키노트 세팅 §5 계층표가 「라벨 · 출처 · 배지 20」 이라고 못박고 있다
② em 으로 두면 본문을 키울 때 배지가 딸려 커져 24 상자를 넘는다
   본문 30 이면 배지 글자가 25.5 가 되어 테두리를 밟는다 · 실측
```

실측 · `--본문` 을 21 · 24 · 30 으로 바꿔도 셋이 함께 움직이고 · 배지는 20 / 상자 26 그대로 ·
격자 어긋남 0.

### 5-10. 단계띠 · 수치 · **한 줄 안에 크기를 섞으면 상자가 벌어진다**

```
단계띠   한 칸 = 42(라벨) + 42 × 내용 줄수      칸은 가로로 균등 · 묶음 높이는 가장 긴 칸
수치     한 칸 = 84(값 + 단위) + 42(라벨) = 126
```

**단계띠에 세로 패딩을 안 준다.** 배경 박스(N-배경)가 나중에 이 사각형에 딱 맞게 깔린다.
세로 패딩을 주면 그만큼 격자에서 밀려난다 · 시각적 여유는 라벨이 제 안에 가진 상하 7 로 낸다.
현재 칸은 지금 **색과 굵기로만** 가른다. 남색 배경은 N-배경 이 얹는다.

**함정 하나가 여기서 드러났다.** 값 52 와 단위 26 을 한 줄에 놓았더니
`line-height:84` 를 줬는데도 **줄 상자가 97 로 나왔다**(+13 · 격자 깨짐).

```
원인   브라우저가 크기가 다른 글자의 기준선을 맞추느라 상자들의 합집합을 잡는다.
       52px 글자의 기준선 위치와 16px 스트럿의 기준선 위치가 달라 그만큼 위로 벌어진다.
고침   height:84 로 못박고 기준선 정렬은 flex(align-items:baseline)에 맡긴다.
```

**한 줄 안에 크기가 다른 글자를 섞을 때마다 이 일이 난다** · §9 ⑫.
`{TBD}` 배지(§5-8)와 뿌리가 같다 — 그쪽은 `inline-block` 이라 제 높이로, 이쪽은 기준선 정렬로.

**줄 예산.** 수치 한 칸이 **3줄**이라 G5 상단(5줄)에는 제목 하나만 붙일 수 있다.
제목 + 요약까지 붙이면 6줄이 되어 넘친다 · 실측으로 확인했다.

### 8-1. 글자를 어디까지 열 것인가 · **판단 재료**

**실측으로 갈렸다. 격자를 깨는 것은 크기가 아니라 행간이다.**

```
본문 20 → 30px 로 바꿔 가며 전수 검사    격자 어긋남 0 · 줄 수도 안 변함
바뀌는 것은 한 줄 글자 수뿐이다          24px 37자 → 30px 30자 (−20%)
```

그래서 경계를 이렇게 그을 수 있다.

| | 무엇 | 왜 |
|---|---|---|
| **절대 잠근다** | **행간** · 언제나 42 의 배수 | 여기만 잠그면 **격자가 깨질 방법이 없다** |
| **계단으로 연다** | **크기** · 자유 숫자가 아니라 정해진 몇 개 | 예산 재계산이 유한하고 규격서에 표로 적힌다 |
| **문서 단위로만** | 계층 아홉의 굵기 · 색 | 자리마다 흔들면 위계가 무너진다 |
| **안 연다** | 자동 축소 | §4-2 가 폐기한 것이다 · 아래 근거 |

**하한은 21px 이다.** 출력 검증된 실물(`_DEV/제안서(200dpi).pdf` · 29면 · Keynote)의
본문이 **21 · 22 · 23** 이라 그보다 작아지면 검증 범위 밖이다. **크게 가는 쪽은 제약이 없다.**

**자동 축소를 막아야 하는 근거가 그 PDF 에 있다.** 8면에서 `14.3 · 13.5 · 15.1px` 같은
소수점 크기가 무더기로 나온다. Keynote 의 「텍스트 자동 축소」가 표를 우겨넣은 자국이고 ·
설계 §4-2 가 폐기한 「밀도를 손으로 맞추는」 실패가 실물에 그대로 남아 있다.

**준비는 끝났다.** `--본문` 하나가 본문 · 목록 항목 · 번호목록 항목을 묶고 있고 ·
배지는 20 고정으로 떼어 놨다(§5-9). **계단 값만 정하면 붙는다.**

| ③ | **`구성` 이 두 시대에서 뜻이 다르다.** 옛 표지 면의 `구성` 을 새 엔진이 「골격 덮어쓰기」로 읽어 `구성에 띠가 없다` 로 죽는다 |
| ④ | **걸음과 칸 폭을 혼동하지 마라.** 옛 체계 `92.73975` 는 걸음이다. P1 · P2 · P2-d 가 세 번 틀렸다 |
| ⑤ | **외장 볼륨 `BridgeNine` 이 마운트에서 빠질 수 있다** |
| ⑥ | **「제목」이 두 뜻이다.** `면.제목` 은 헤더 밴드(폭 2179 · 안 접힌다) · `자리.제목` 은 자리 안이다. 줄바꿈을 잴 때 섞으면 값이 무의미해진다. 실제로 한 번 섞어 재서 「45개 중 17개가 두 줄」이라는 틀린 값을 냈다. **면 제목 39 · 블록 제목 6 이 맞다** |
| ⑦ | **문안 파일을 밖에서 고치면 개발 서버를 재시작해야 반영된다** |
| ⑧ | **`--문단사이` · `--머리뒤` 는 0 또는 42 만 쓴다.** 21 을 쓰면 문단마다 격자가 홀짝으로 엇갈린다 |
| ⑨ | **§5-2 「한 줄 글자」 표는 일부러 보수적이다.** `폭 ÷ 24` 는 전각 가정이고 실제 산문은 평균 19~20px 라 **실측이 30% 더 들어간다**(632px 에 26자 표기 · 34자 실측). 틀린 값이 아니다. 규격서에는 표의 값을 쓴다 |
| ⑩ | **비교본을 만들 때는 문안을 예산에 꽉 채운다.** 안 채우면 안마다 값이 똑같이 「안 넘침」으로 나와 **치르는 값이 안 보인다.** N-글자 b 에서 두 번 다시 짰다 |
| ⑪ | **`display:inline-block` 은 제 높이로 줄 상자를 밀어 올린다.** 행간 42 를 물려받으면 42 + 테두리 = 44 가 되어 그 줄만 격자에서 밀린다. **새 인라인 조각을 만들 때마다 제 행간을 함께 준다** · §5-8 |
| ⑫ | **한 줄 안에 크기가 다른 글자를 섞으면 줄 상자가 `line-height` 보다 커진다.** 기준선을 맞추느라 상자들의 합집합이 잡힌다. 값 52 + 단위 26 에서 84 → 97 이 나왔다. **`height` 로 못박고 정렬은 flex 에 맡긴다** · §5-10 |

## §11 한 줄 요약
