# 원고 규격서 · 제안서

> **원고를 쓰기 전에 이 문서를 읽는다.** 챗 세션이 매번 읽는 고정 문서다 · 한 번 읽고 마는 글이 아니다.
> 판정 기준은 이 문서가 아니라 **렌더러**다 · `render/index.js`. 여기 적힌 것은 그 계약을 사람 말로 옮긴 것이고 ·
> 어긋나면 렌더러가 이긴다. 어긋난 자리를 찾으면 고쳐 달라고 말해 달라.
>
> 갱신은 `node scripts/예산.mjs --규격` 이 §4 를 다시 쓴다 · 그 구역은 손으로 고치지 마라.

---

## §0 누가 무엇을 맡나

```
원고(챗)      내용과 구조        무엇을 쓸지 · 어느 박스에 담을지 · 어느 레이아웃에 앉힐지
변환기        원고 → JSON       문법만 본다 · 조판 열쇠를 원고에서 안 받는다
편집기(사람)   꼴과 좌표          표 열 폭 · 그림 높이 · 도형 · 색 · 얹기 · 구간 표기
```

**원고는 조판을 모른다.** px · 42 블록 수 · 열 폭 · 색을 적지 마라. 적으면 변환기가 오류로 막는다.

**왕복은 단방향이다.** 원고 → JSON 으로만 간다. 편집기에서 손본 것은 원고로 안 돌아온다.
고칠 것이 생기면 **그 페이지만 다시 만든다** · 전체를 다시 내지 않는다.

## §1 원고가 낼 수 있는 것 · **닫혔다**

여기 없는 것은 낼 수 없다.

```
페이지   번호 · 제목 · 모드(카피 · 연속) · 레이아웃(G1 ~ G12)
밴드     카피(메인 · 서브) · 요지
박스     제목 · 문단 · 목록 · 번호목록 · 표 · 그림 · 출처 · 비움
표기     **굵게** 하나
```

## §2 문법

마크다운이다. **요소마다 꼴이 하나씩이고 · 겹치지 않는다.**

### 2-1 페이지 하나

```markdown
# 01 · 타임테이블

모드: 연속
레이아웃: G3
요지: 계약일 D 를 기준으로 15주를 짠다

## 박스
### 주 단위 일정
D 를 계약 체결일로 놓는다. 착수보고는 **D+7일 이내**다.

## 박스
### 확인 사항
- 서식 9종을 D 이전에 낸다
- 계정 발급은 협약 통보 다음 날이다

## 박스
### 산출물
> 착수보고서 · 심사표 · 협약서
```

**`# ` 한 줄이 페이지 하나를 연다.** `번호 · 제목` 꼴이다 · 번호는 두 자리 문자열로 적는다(`01`).

**열쇠 줄 넷은 제목 바로 아래 둔다.** `모드` 와 `레이아웃` 은 **반드시** 적는다 · `요지` 는 없으면 뺀다.

```
모드: 카피          첫 장 · 장 여는 면 · 카피 밴드가 선다
모드: 연속          본문 면 · 밴드가 낮고 박스가 높다
레이아웃: G3        §3 에서 고른다
요지: …             면 전체를 한 줄로 말한다 · 밴드에 앉는다
```

`모드: 카피` 일 때만 카피 두 줄을 더 쓸 수 있다.

```
모드: 카피
레이아웃: G2
카피 메인: 38억원을 세 축으로 나눈다
카피 서브: 속성이 요소가 아니라 몇 글자에 걸린다
요지: 사업비를 셋으로 가른다
```

### 2-2 박스

**`## 박스` 한 줄이 박스 하나를 연다.** 박스 수는 **레이아웃이 정한 칸 수와 정확히 같아야 한다**(§3).
모자라거나 남으면 변환기가 그 자리에서 막는다.

**빈 칸을 두려면 `## 박스` 아래를 비우지 말고 비움을 적는다**(2-4).

### 2-3 박스 안 요소

| 쓸 것 | 꼴 | 렌더러 열쇠 |
|---|---|---|
| 제목 | `### 주 단위 일정` | `제목` |
| 문단 | 그냥 한 줄 · 빈 줄로 가른다 | `문단` |
| 목록 | `- 항목` | `목록` |
| 번호목록 | `1. 항목` | `번호목록` |
| 표 | 마크다운 표 | `표` |
| 그림 | `![설명](assets/캡처/x.svg)` | `그림` |
| 출처 | `> 출처 · 라벨` | `출처` |
| 비움 | `[비움: 단계띠]` | `비움` |

**순서는 자유다.** 「문단 → 그림 → 문단」도 된다. 같은 갈래를 여러 번 써도 된다.

**문단은 빈 줄로 가른다.** 한 문단이 여러 줄이면 그대로 한 요소다.

**표는 헤더 줄을 쓴다.** 열 폭은 **적지 마라** — 균등으로 나가고 사람이 편집기에서 손본다.
표 50건 중 44건이 불균등 폭을 들고 있었는데(봉인본 39쪽 실측) 그건 칸 안 글자를 보고
사람이 그 자리에서 정한 값이라 마크다운이 못 나른다.

```markdown
| 시점 | 단계 | 수행 내용 |
| --- | --- | --- |
| **D** | 착수 | 계약 체결 · 착수보고 |
| **D+1주** | 모집 | 의향 재확인 · 추가 공모 |
```

**그림은 경로만 준다.** `assets/` 로 시작하는 레포 기준 상대경로다 · `png · jpg · svg · webp · gif`.
높이를 적지 마라 · 변환기가 기본값을 앉히고 사람이 편집기에서 끈다(§5-1).
**문단 · 목록과 한 박스에 섞어 써도 된다.**

### 2-4 비움 · 앱이 못 그리는 것

단계띠 · 지도처럼 **앱이 안 그리는 물건**은 자리만 비워 두고 키노트에서 채운다.

```markdown
[비움: 단계띠]
[비움: 지도]
```

**무엇을 넘길지만 적는다.** 높이는 변환기가 기본값으로 앉히고 사람이 끈다.

```
단계띠   3 블록      봉인본 7건 실측 중앙값
지도     8 블록      봉인본 1건 실측
```

### 2-5 표기 · **굵게 하나뿐이다**

```markdown
착수보고는 **D+7일 이내**다.
```

색 · 크기 · 자간 · 밑줄 · 기울임은 **못 쓴다.** 편집기가 드래그로 입힌다.

## §3 레이아웃 열둘 · 고르는 기준

**박스 수가 곧 레이아웃이다.** 먼저 「이 면에 덩어리가 몇 개인가」를 세고 · 그 수를 내는 것 중에서 고른다.

**이름은 렌더러가 붙인 것 그대로다** · `render/index.js` 의 `레이아웃`.

| 레이아웃 | 칸 | 이름 | 어떤 자리인가 |
|---|---|---|---|
| G1 | 1 | 전면 | 한 덩어리가 면을 다 먹는다 · 표지 · 총론 |
| G2 | 2 | 좌우 둘 | 나란한 둘 · 견줌 |
| G11 | 2 | 2열 폭 2:1 | **왼쪽이 넓다** · 본문 + 곁칸 |
| G12 | 2 | 2열 폭 1:2 | **오른쪽이 넓다** · 곁칸 + 본문 |
| G3 | 3 | 3열 | 나란한 셋 |
| G4 | 3 | 좌1 : 우2 | 왼쪽 한 칸이 주인 · 오른쪽이 위아래로 갈린다 |
| G5 | 3 | 상1 : 하2 | 위 가로 띠가 총론 · 아래 둘이 각론 |
| G6 | 4 | 4열 | 나란한 넷 · 칸이 좁다(25자) |
| G7 | 4 | 2 × 2 | 두 축을 교차시킬 때 |
| G8 | 4 | 상3열 : 하전면 | 위 셋이 각론 · 아래 한 칸이 결론 |
| G10 | 5 | 3열 · 2 · 1 · 2 | 가운데 칸만 통으로 높다 |
| G9 | 6 | 3열 · 박스 둘 | 여섯 · 칸마다 11 ~ 12줄뿐이다 |

**고르는 차례**

```
1  덩어리를 센다                   셋이면 G3 · G4 · G5 중에서 고른다
2  덩어리의 성격을 본다             나란한 셋이면 G3 · 하나가 주인이면 G4
                                 앞에 총론 한 줄이 있으면 G5
3  예산을 본다                     §4 에서 그 칸이 몇 줄인지 보고 글을 그 안에 맞춘다
```

**칸이 많을수록 칸마다 줄이 급히 준다.** G9 연속은 칸마다 11 ~ 12줄이고 · 제목을 붙이면 9 ~ 10줄이다.
**여섯 덩어리를 억지로 만들지 마라** · 셋으로 묶어 G3 에 넣는 편이 거의 언제나 낫다.

## §5 못 쓰는 것 · 왜

| 못 쓴다 | 왜 |
|---|---|
| 요약(제목 밑 한 줄) | 봉인본 39쪽에 0건이다 · 문법을 늘릴 값이 없다 · 편집기에서 넣는다 |
| 수치(큰 숫자 칸) | 39쪽에 4건 · 2% 도 안 된다 · 편집기에서 넣는다 |
| 빈칸 | 조판상의 틈이다 · 42 블록 수는 원고가 아는 물건이 아니다 |
| 표 열 폭 · 정렬 | 칸 안 글자를 보고 정하는 값이라 마크다운이 못 나른다 |
| 그림 높이 | 조판 열쇠다 |
| 도형 · 배경 · 얹기 · 선 | 판에 얹는 층이다 · 레이아웃과 무관하게 사람이 놓는다 |
| 색 · 크기 · 자간 | 편집기가 드래그로 입힌다 |

### 5-1 변환기가 대신 앉히는 것 둘

**원고가 못 주는 조판 열쇠 중에 둘은 비워 두면 안 되는 자리다.** 변환기가 기본값을 넣고 · 사람이 편집기에서 끈다.

```
그림 높이     기본값을 앉힌다        원고는 경로만 준다
비움 블록 수   단계띠 3 · 지도 8      원고는 무엇을 넘길지만 적는다
```

**그림에 높이가 있어야 하는 이유**는 렌더러 계약이다 · `render/index.js:874~883`.
높이가 없는 그림은 「남은 높이를 먹는 요소」가 되는데 · 남은 높이를 재려면 같은 박스의
문단 · 목록 줄 수를 미리 알아야 하고 그건 글자에 달려 브라우저 없이 못 센다.

**그러니 원고 쪽에서는 신경 쓸 것이 없다.** 그림과 문단을 한 박스에 자유롭게 섞어 써라 ·
순서도 자유다. 실측으로 확인했다.

```
제목 + 그림 + 문단 + 출처      된다
그림 + 목록                  된다
그림 둘 + 문단                된다
```

## §6 되먹임 고리 · **한 번에 맞게 쓸 수 없다**

분량이 글자 수가 아니라 **줄 수**로 걸리고 · 줄 수는 재야 나온다.
「원고 → 검사 → 원고 고치기」가 **정상 경로**다. 실패가 아니다.

```
원고 .md  →  변환기  →  JSON  →  넘침 검사  ─┐
   ↑                                        │
   └────  「03쪽 박스 2 · 예산 24줄 · 실제 27줄 · 3줄 줄인다」  ←┘
```

**되돌아오는 말은 이 꼴이다.**

```
03쪽 · 박스 2 · 예산 24줄 · 실제 27줄 · 3줄 넘쳤다
11쪽 · 레이아웃 G6 은 칸이 4개인데 박스가 3개다
14쪽 · 박스 1 · 표 2행이 3칸이다 · 열 수 4 와 맞춘다
```

**쪽 번호와 박스 번호가 붙어 온다.** 그 페이지만 다시 써서 주면 된다 · 전체를 다시 내지 마라.

## §7 예산이 이런 글을 강제한다

**한 줄에 몇 자인지가 문장 길이를 정한다.** G3 연속 한 칸은 37자 × 26줄이다 ·
제목을 달면 24줄이고 · 출처까지 달면 23줄이다. **962자가 아니라 851자가 실제 몫이다.**

그래서 이런 글이 된다.

```
한 문장이 한 줄 안팎이다        37자를 넘기면 둘째 줄로 넘어가고 · 줄은 곧 예산이다
접속사를 줄인다                「그러므로」 한 낱말이 한 줄의 8분의 1이다
목록이 문단보다 싸다            항목 하나가 정확히 한 줄이고 · 사이 간격이 0이다
표가 가장 싸다                 행 하나가 한 줄이다 · 헤더까지 세면 (행 + 1)줄
```

**문체 본론은 이 문서 밖이다.** 여기서 정하는 것은 「몇 줄에 담기느냐」까지고 ·
어떤 어투로 쓰느냐는 별도 문체 기준집이 맡는다.
